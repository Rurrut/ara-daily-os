## 아직 확인이 필요한 항목

- Android 2.7을 실제 휴대폰에 설치한 뒤 10월 20일 기록의 노션 전송 성공 여부
- 당시 HTTP 400이 인증 갱신 거절인지 세션 만료인지에 대한 정확한 원인
- 기기별 절전·알림 권한·백그라운드 제한 아래의 실제 전달 시점
- 사용자별로 다른 루틴과 우선순위에 대한 일반화
- 서로 다른 기기에서 같은 범위를 동시에 편집하는 여러 실제 상황

Google Calendar 연동과 앱 내 AI 자동 분석은 구현된 기능으로 소개하지 않습니다. 노션 데이터베이스는 읽기와 기록 저장에 사용하며, 현재 PC·휴대폰 동기화를 대신하지 않습니다.

## 체크리스트 추가 후 확인

모바일 DOM 대역 71개와 PC 자체 검사 258개를 통과했다. PC의 새 검사 7개에는 실제 기록 보존, 할 일별 병합 구분, 저장·불러오기, 완료 체크와 PC 점수 변경의 동기화 병합이 포함된다.

390px 너비의 실제 브라우저에서 할 일 추가, 끌어 놓아 기록하기, 집중·만족도 연속 입력, 메뉴의 완료 체크, 목록 반영과 새로 열었을 때 보존을 확인했다. 일반 드래그는 이동 경로를 기록하지 않고 도착한 한 칸만 기록한다. 시작 칸에 멈춘 뒤 확장하는 입력·취소 경로는 DOM 대역으로도 확인한다.

PC 실행 파일과 서명된 화면 2026102103을 적용했고, 실행 중인 PC의 다운로드 해시와 기존 기록·할 일 보존을 확인했다. 실제 Android 기기의 터치와 양 기기 왕복 동기화는 이번 브라우저·대역 검증만으로 확인했다고 보지 않는다.

## Android 2.8 인증 거절 처리

휴대폰에서 인증 만료·갱신 거절 400이 다시 보고되었다. 이 안내는 `/token`의 `invalid_grant` 또는 `invalid_client` 분류에서 나온다. 해당 기기의 상세 사유는 확인하지 못했으므로 토큰 재사용, 서버 만료, 클라이언트 불일치 중 하나를 원인으로 단정하지 않는다.

거절된 인증으로 계속 갱신을 시도하던 처리를 중단하고, 상태를 저장해 앱을 다시 열어도 재연결 필요 상태가 유지되도록 수정했다. 저장 위치와 전송 대기 기록은 유지하며, 인증 거절 뒤에는 연결됨으로 표시하지 않는다. 인증 사유 코드와 시각만 진단 상태에 포함한다. 일반 서버 오류는 재연결 필요로 처리하지 않는다.

네이티브 HTTP 대역 검사 33개로 기존 세션 처리와 새 거절 중단·재실행 보존·정상 갱신·재연결 상태 해제 경로를 확인했다. Android 작업 스케줄러 취소와 성공한 로그인 뒤 대기 전송 재개는 소스·빌드로 확인했으며, 실제 휴대폰의 로그인과 전송 성공은 아직 확인하지 못했다. 기존에 거절된 인증은 업데이트 후 한 번 다시 연결해야 한다.

공식 근거: [Notion MCP 인증 갱신 지침](https://developers.notion.com/guides/mcp/build-mcp-client#handling-invalid_grant).

## Android 2.8.1 재로그인 실패 표시

2.8에서 재로그인 실패도 다시 400으로 보고되었다. 확인 결과 재연결 필요 상태에서는 이전 갱신 오류가 새 로그인 오류를 가릴 수 있었다. 최신 로그인 결과를 우선 표시하고 재실행 뒤에도 유지하도록 수정했다. 브라우저의 콜백 완료 화면에도 실패 단계·HTTP 상태·허용한 사유 코드만 표시한다. 원문 서버 응답과 인증 값은 표시하지 않는다.

네이티브 대역 검사 44개를 통과했다. 새 로그인 오류 우선 표시, 재실행 후 보존, 브라우저 안내의 민감 정보·HTML 배제, 로그인 코드·PKCE·리디렉션 값의 정확한 폼 인코딩, 잘못된 응답에서 저장 위치 보존을 포함한다. 노션 서버의 공개 메타데이터와 일회성 앱 등록도 직접 확인했고, 요청한 `none` 인증 방식으로 등록되며 client secret이 반환되지 않는 것을 확인했다. 등록 방식이 원인이라고 단정할 근거는 없었다.

이 수정은 재로그인 성공을 확인한 수정이 아니다. 실제 휴대폰의 최신 로그인 실패 코드를 확인해야 400의 원인을 더 좁힐 수 있다. 코드 교환 실패, PKCE·리디렉션·만료 등은 서버 설명에 해당 문구가 있을 때만 제한된 분류로 표시한다.

## Android 2.9 앱 업데이트 메뉴

실제 APK 설치 대신 화면만 다시 열고 있던 혼동을 수정했다. 설치 버전이 2.7로 고정 표시되는 문제도 있었다. 이제 Android 패키지 정보와 활성 화면 버전을 표시하고, 새 APK가 있으면 앱 업데이트 설치를 우선 제공한다.

모바일 입력·업데이트 메뉴 대역 75개, 공개 다운로드 경로 검사 25개, 노션 인증 회귀 44개를 통과했다. 공개 GitHub 조회에 PC 토큰을 전달하지 않으며, 다운로드 해시·화면 서명·Android 패키지 서명 검증을 유지한다. 실제 기기에서의 설치 승인과 설치 완료는 별도 확인이 필요하다.

GitHub 릴리스 API의 배열 순서가 발행 시각 순서와 다른 경우를 실제 조회에서 확인했다. 최종 2.9.1에서는 발행 시각이 가장 늦은 준비된 릴리스를 선택하며, 이 경로를 회귀 검사에 포함했다.

## Android 2.9.2 노션 로컬 오류 진단

휴대폰 Wi-Fi와 모바일 데이터 모두에서 코드 교환이 local_error로 끝난다는 보고를 받았다. 기존 구현이 HTTP 외 예외를 하나로 표시해 원인은 아직 확인하지 못했다. TLS, DNS, 연결 시간 초과, 연결 중단, JSON 해석 오류를 고정 코드로 구분하고 마지막 진단을 저장한다. 예외 메시지와 응답 본문은 노출하지 않는다. 실제 휴대폰 재연결 결과 확인이 남아 있으며 로그인 성공을 보장하는 수정은 아니다.
