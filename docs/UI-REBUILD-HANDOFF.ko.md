# Aiary 화면·계획 편집·렌더링 재설계

작성일: 2026-11-04. 기준 코드: 4378fea. 이 문서는 다음 구현 모델이 사용할 실행 명세다. `ui-redesign-preview.html`은 상호작용 가능한 시안이며 실제 기록 저장 앱이 아니다.

## 1. 완료 범위와 증거

- 소스 수정: `mobile/mobile.js`의 `renderActualBlockSummaries`에서 이전 요약 오버레이를 제거하고 재작성한다. 실제 칸 인덱스를 Map으로 만들어 칸마다 CSS 선택자로 전체 DOM을 검색하던 작업을 줄였다. 쓰기 직후 `getComputedStyle` 읽기를 CSS 변수 읽기로 바꿨다.
- 아라의 큰 base64 배경 문자열을 같은 요소에 매번 다시 할당하지 않는다. 원본 에셋 자체는 변경하지 않았다.
- 날짜 줄의 ‘계획’ 버튼에 오늘 계획 목록과 새 계획 입력 폼을 연결했다. 기존 `detail` 명령으로 계획 레인을 저장하며, 10분 단위 시각·길이 선택, 겹침 거부, 카테고리 색상 표시, 계획 선택 후 기존 블록 이동/길이 조절 흐름을 재사용한다. 시간표 렌더 범위는 계획 블록의 시작·끝을 포함한다.
- 시간 표시용 전체 칸 순회는 현재 10분 구간이 바뀔 때만 실행한다. 전체 스냅샷/렌더 주기를 매 15초에서 10분 경계로 낮췄다. 기록이 바뀌면 기존처럼 즉시 갱신한다.
- Chrome 실제 DOM에서 한 기록으로 render 100회: 수정 전 요약 노드 100개, 수정 후 1개. 양쪽 설정창 열림. 원시 결과: `../work/ui-review-20261104/render-probe.json`(저장소 상위 work 기준).
- `node mobile/tests.cjs`: 81/81 통과. 계획 목록 선택, 새 계획의 기존 엔진 명령, 계획 겹침 거부를 포함한다. 이 테스트는 간이 DOM 테스트이며 Android 검증을 대체하지 않는다.
- 가상 시간 기반 브라우저 시험에서 performance.now 값이 0으로 나왔으므로 처리 시간 결과는 폐기했다. 모바일 FPS·P95 지연·메모리 수치는 아직 없다.
- 실제 Edge 브라우저에서 14개 계획 표시와 입력 폼 필드/시간 선택을 확인했다. 저장 버튼은 브라우저에서 누르지 않아 사용자 기록을 바꾸지 않았다. 화면 번들은 설치 앱의 기존 공개키에 대응하는 로컬 서명키로 서명해 GitHub `v2.12.4-ui.2026110401`에 배포했다. 기존 APK 2.12.4(코드 33)는 그대로 재사용했다. APK 설치 없이 화면 업데이트를 받을 수 있는 구성이다. 물리 Android에서 업데이트 수신·WebView·터치 동작을 확인하지는 않았다.

## 2. 제품·화면 계약

사용자가 준 다크/라이트 이미지는 색감과 분위기의 기준이다. 이미지의 오타·잘못된 시간 표기는 복사하지 않는다. 브랜드는 Aiary, 안내 캐릭터 이름은 아라다.

1. 위는 계획, 아래는 실제 기록. 한 시간에 각각 6칸, 한 칸 10분을 유지한다. 기존 사용자가 원치 않았던 반복적인 계획/실제 텍스트 라벨은 기본으로 넣지 않는다. 행 색과 간격으로 구분하고 접근성 이름에는 구분을 넣는다.
2. 라이트는 크림 배경 #F7F4E9, 잉크 #344335, 세이지 포인트 #739957. 다크는 #111D17, 잉크 #E5ECDF, 포인트 #8EB66B. 계획 빈칸은 낮은 대비, 실제 빈칸은 약간 차가운 녹색. 점수 색 보기에서는 카테고리 배경색과 점수 색이 섞이지 않게 하나만 적용한다.
3. 폰 390px 기준 좌우 8px, 시간 열 30px, 칸 간격 3px. 계획 행 22~26px, 실제 행 32~36px. 임의로 글자를 7px까지 줄이지 않는다. 한 칸에는 활동 이름만, 상세 수치는 선택 메뉴에서 보여준다. 2칸은 이름+기간, 3칸 이상은 집중 게이지·만족도 표정·작은 이행 비교를 표시한다.
4. 상단은 날짜, 기상·수면·집중·만족·이행, 색 보기 순서. 상태 표시줄 안전 공간은 기존 18px 정책을 유지한다. 큰 캐릭터 전용 상단 영역은 금지한다.
5. 아라는 시간표 위 fixed overlay로 유지한다. 오른쪽 아래 조작 버튼 위에 58px 아이콘, 왼쪽 말풍선. 아이콘 탭으로 접기/열기. 컨텍스트 메뉴·편집창보다 낮은 z-index. 말풍선이 접히면 시간표를 차지하는 투명 클릭 영역도 없어야 한다.
6. 장식은 모서리에 작은 클로버 정도로 제한한다. 매 칸 그림자·blur·무한 애니메이션은 사용하지 않는다. 큰 배경 그림은 내용보다 낮은 대비, pointer-events:none, 스크린리더 제외.

## 3. 계획하기 화면과 상호작용

날짜 줄의 작은 ‘계획’ 버튼은 바닥에서 올라오는 계획 패널을 연다. 타임테이블을 새 화면으로 교체하지 않는다. 현재 계획 목록/새 계획 입력까지 구현되어 있으며 반복 프리셋과 자동 조정 미리보기는 설계 범위로 남아 있다.

- ‘오늘 계획’: 계획 활동 목록을 시간순으로 표시. 항목 선택 시 해당 계획 블록으로 스크롤하고 선택한다. 이후 이동·양끝 늘리기는 현재 동작을 재사용한다.
- ‘활동 추가’: 계획 범위가 선택되어 있으면 그 범위의 길이를 기본값으로 사용한다. 없으면 현재 또는 기상 이후 첫 빈 10분 칸을 제안한다. 활동명은 선택, 카테고리는 필수. 시작과 길이는 10분 단위 선택기로 입력한다. 기존 계획과 겹치면 저장을 거부한다.
- ‘반복 계획’: 평일/주말/요일별 프리셋은 별도 탭. 첫 구현에서는 저장된 프리셋 적용 미리보기까지, 자동 개인화 학습은 포함하지 않는다.
- 적용 전 이동/축소/제외되는 미래 활동을 반투명으로 미리 보여준다. 적용과 취소를 제공하고 실제 저장은 적용 때 한 번만 한다.
- 실제 기록이 존재하는 활동과 과거 계획은 자동 변경하지 않는다. 사용자의 명시적 계획 수정은 별도 명령으로 기록하며 실행취소 가능해야 한다.
- 계획→실제 드래그는 복사, 계획 내 드래그는 이동, 실제 내 드래그는 이동이다. 위/아래 범위 선택은 각각 해당 행만 통과한다. 이미 있는 기록을 묵시적으로 덮어쓰지 않는다.
- 충돌 시 ‘빈칸으로 옮기기’ 안내와 충돌 블록 강조. 편집 대기열에 실패 명령을 넣고 계속 재시도하지 않는다.

패널 API는 UI 상태만 관리한다. 저장 시 기존 엔진 명령 생성기를 호출한다. 기존 command schema를 읽고 그대로 사용하며 `plan-add` 같은 새 op를 UI에서 임의로 만들지 않는다. 신규 op가 필요하면 engine, 저장, undo, sync 모두 동시에 정의한다.

## 4. 기록 깨짐과 병목 진단

확인된 결함: 기존 `renderActualBlockSummaries`는 이미 있는 `.actual-block-overlay`를 재사용하면서 `.actual-block-content`를 계속 append했다. 전체 render마다 같은 글자가 쌓여 겹치며, DOM 수가 계속 증가한다. 이번 응급 수정으로 누적을 막았다.

추가로 코드에서 확인한 비용 경로(실측 병목으로 단정하지 말 것):

- 15초 타이머: `E.snapshot(R.state(), A.date)`와 전체 render를 매번 실행한다.
- render: 모든 타일에서 활동 배열 find, 지난 계획 find, 점수 액션 find를 반복한다.
- paintSelection: 선택 변경 때 전체 타일 검색 및 손잡이 제거/재생성. 손잡이 터치 중 DOM 교체는 금지되어 있어 별도 유지 분기가 존재한다.
- 요약 렌더: 실제 칸마다 selector 검색 및 스타일 쓰기 뒤 computed style 읽기가 섞였다. 이번 수정으로 이 부분 검색/읽기는 줄였다.
- 아라: 큰 이미지 문자열 재할당과 안내 DOM 재작성. 이미지 재할당은 줄였지만 말풍선 key 기반 패치는 추가 필요하다.
- CSS가 여러 차례 override되는 구조다. 삭제/정리 없이 새 테마를 계속 끝에 붙이지 않는다.

## 5. 목표 구조

빌드 결과는 기존 Android가 읽는 index.html/mobile.css/offline-core.js/mobile.js 계약을 우선 유지한다. 개발 소스를 분리해도 배포 시 합친다. 파일을 늘리려면 `AppUpdates.unpack`, 서명 대상 목록, native APK asset loader를 먼저 함께 수정한다.

- `state/day-store`: authoritative day + revision. record/plan/category 변경만 revision 증가. theme/selection/clock은 별도 UI 상태다.
- `selectors/day-view`: revision + displayDate를 키로 활동을 인덱싱. plannedBySlot[288], actualBySlot[288], previousBySlot[288], actionById를 한 번 생성. DOM 의존성 없음.
- `scheduler/commands`: 순수 계산. 입력 state+command, 출력 nextState+changedRanges+adjustmentEvents. 과거·진행 중 계획 보존 및 취침 고정 규칙은 기존 엔진 테스트를 그대로 통과해야 한다.
- `render/timeline`: 시간 행 keyed DOM. 288칸 범위는 고정 크기이므로 먼저 DOM 누적/전체 갱신부터 해결하고, 가상 스크롤은 실측 후 판단한다.
- `render/segments`: 활동을 시간 경계로 분할해 각 행에 표시. 첫 구간에 주 제목, 이어지는 구간에는 이어짐 표시. ‘가장 긴 한 구간에만 제목’ 정책을 폐기한다. 시각적으로 합쳐도 원래 block id/score/satisfaction/taskId는 보존한다.
- `render/header`: 점수 값이 바뀐 경우에만 textContent 갱신.
- `interaction/gesture`: pointer/touch 상태기계 idle/select/move/resize. requestAnimationFrame당 최대 1회 화면 반영. pointerup에서 1회 command commit. 중간 이동은 저장·동기화·일정 재계산 금지.
- `ara/controller`: intent key(date, trigger, blockId)로 메시지를 선택. 표시 중 메시지가 같으면 DOM 변경 없음. 미확인 후보는 실제 기록과 별도 저장하며 집계/노션에 포함하지 않는다.
- `sync/coordinator`: 외부 응답은 revision 비교 후 반영. gesture 중에는 큐에 보관하고 종료 후 처리. 낙관적 상태/최종 상태를 이중 append하지 않는다.

## 6. 갱신 규칙

기록 저장 → engine 한 번 → changed slot/segment만 패치 → header 재집계 → 비동기 동기화 예약.

선택 이동 → 이전 선택과 새 선택의 차이 칸만 class 토글. 기록/계획 데이터 변경 없음.

10분 경계 → 현재 칸 마커 2개 이동. 만족도 현재 시각 집계만 새로 계산. 15초마다 schedule 전체 snapshot/render 금지.

앱 resume → 기상일 정책으로 날짜 갱신 → 필요한 경우 하루 view 재구성 → 알림 재등록은 일정 revision이 바뀐 경우만.

테마 변경 → CSS 변수 변경. 점수/카테고리 채움은 테마에 맞춰 한 번 패치. read/write를 섞지 않고 geometry 읽기 단계 후 DOM 쓰기 단계 실행.

## 7. 에셋 처리

`ui-assets/ara-sheet.png`는 앱에 내장돼 있던 PNG를 바이트 그대로 추출한 원본이다. 새 아라를 그리지 않았다. 시안은 CSS로 해당 표정만 보여준다. 실제 배포 JS에서 base64를 제거하려면 앞의 번들 호환 계약을 먼저 변경해야 한다.

후속 에셋 작업: 원본 시트의 아침/기본/밤×4표정 12개를 투명 PNG/WebP로 정확히 분리한다. 현재 148px 원형 crop은 모자/머리와 흰 배경이 남는 임시 방법이다. 캐릭터 윤곽을 보존하고 흰색을 일괄 투명화하여 눈/구름이 사라지는 방식은 금지한다. 각 에셋에 동일한 얼굴 중심/베이스라인을 적용하고 1x·2x에서 검수한다. 모션은 CSS 이동/불투명도 120~180ms, reduced-motion 지원. 날씨별 기능은 보류한다.

## 8. 구현 순서와 통과 기준

1. 이번 누적 수정부터 보존. 실제 DOM에 1/3/6/9칸 기록을 넣고 100회 render 뒤 노드 수가 고정인지 확인. 삭제 후 요약 0개, 날짜 전환 후 이전 날짜 요약 0개.
2. segments/selectors 순수 함수 분리. 자정·시간 경계, 다른 점수의 인접 같은 카테고리, task 연결, meal-prep를 포함한 fixture 작성.
3. UI 토큰/스타일 중복 정리. 320/360/390/430px, 밝은/다크, 큰 글꼴에서 수평 넘침·버튼 가림 검수.
4. 계획 패널을 기존 명령 계층에 연결. 오프라인 생성·이동·resize·undo 후 재시작 유지, 이후 동기화 충돌 테스트.
5. 이벤트별 부분 render 및 gesture RAF. Chrome 실제 시계로 warmup 20회 후 200회 측정. trace에 JS/style/layout/paint 시간 분리. Android 실기에서 별도 측정.
6. 목표(미달 시 원인과 결과 보고): 드래그 시 프레임 작업 P95 16.7ms 이하, 단일 기록 반영 100ms 이하, 10분 사용 후 DOM 노드 수 증가 없음. 목표를 측정 결과처럼 적지 않는다.
7. APK 서명·manifest 해시·배포 asset 검증 + APK에서 추출한 실제 HTML/JS로 cold boot, settings, 계획 추가, 기록, undo를 시험. 이후 물리 Android의 WebView/알림/노션을 별도 확인한다.
