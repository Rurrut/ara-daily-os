# 앱 업데이트

Android 2.9부터 설정 → 앱 업데이트 → 업데이트 확인 → 앱 업데이트 설치로 새 APK를 받을 수 있다. 직접 확인할 때는 공개 GitHub 릴리스를 우선 사용한다. 같은 Wi-Fi의 PC 연결이 없어도 인터넷으로 확인하고 설치 화면까지 진행한다. Android 설치 승인과 필요한 설치 허용은 사용자가 기기에서 진행한다.

새 APK가 있으면 화면 적용 버튼은 숨긴다. 화면만 다시 여는 것을 앱 업데이트 완료로 오해하지 않도록 구분했다. 화면 변경만 있을 때는 준비된 화면 적용을 따로 제공한다. 설치 버전은 Android 패키지 정보에서 읽으며, 사용 중인 화면 버전도 현재 값을 표시한다.

2.8.1 이하 앱에는 외부 업데이트 경로가 없다. **처음 한 번은 2.9 APK를 직접 설치하거나, 같은 Wi-Fi에서 PC를 통해 새 APK 설치를 진행해야 한다.** 앱을 삭제하지 않고 기존 앱 위에 설치한다. 화면 업데이트만으로 Android 기능이 추가되지는 않는다.

자동 확인은 15분 간격 제한을 두며, PC가 연결되어 있으면 PC를 우선 사용하고 연결하지 못하면 GitHub를 확인한다. 직접 확인은 GitHub를 우선 사용하고 실패하면 연결된 PC를 시도한다. 연결 실패를 새 버전 없음으로 표시하지 않는다.

GitHub 요청에는 PC 연결 토큰을 넣지 않는다. 허용한 저장소와 HTTPS 다운로드 호스트만 사용하고 리디렉션 횟수·파일 크기를 제한한다. 화면 업데이트는 기존 RSA 서명을, APK는 해시와 기존 앱의 패키지·서명·상위 버전을 확인한 뒤 사용한다. 기록·노션 인증·전송 대기 데이터는 GitHub로 보내지 않는다.

## 배포할 때

새 릴리스에 아래 파일을 모두 첨부한다. 현재 개발 단계에서는 사전 공개 릴리스도 검색 대상이다.

- `ARA-Daily-OS-Android-<versionName>.apk`
- `mobile-update.zip`: 서명한 화면 묶음
- `ara-update.json`: PC의 `mobile-update.json`과 같은 업데이트 정보

APK와 화면 묶음을 먼저 올리고 업데이트 정보 파일을 마지막에 올린다. SHA256·서명·호환 범위를 맞춘 뒤 배포한다. Windows ZIP과 설치 안내·검증값은 함께 제공한다.

공개 GitHub 릴리스 조회와 다운로드 경로를 대역 검사로 확인했다. 실제 배포 후 동일 Java 코드로 업데이트 정보·APK·서명된 화면을 내려받아 확인한다. 실제 Android 설치 화면에서의 사용자 승인과 설치 완료는 기기 확인이 별도로 필요하다.
