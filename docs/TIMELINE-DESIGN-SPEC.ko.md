# Aiary 타임라인 디자인 구현 명세

작성일: 2026-11-05 (Asia/Seoul)
상태: 구현 및 화면 업데이트 배포 완료 (`v2.12.4-ui.2026110501`).
대상: 기존 personal/Preview 공용 모바일 화면. 다음 구현 모델이 적용할 명세다.
우선순위: 이번 사용자 결정 > 이 명세의 확정 항목 > 기존 UI-REBUILD-HANDOFF.ko.md의 디자인 제안. 기존 기능·데이터 보호 조건은 계속 적용한다.

## 1. 사용자 확정 사항

- 카테고리 / 집중 / 만족도 색상 전환 탭을 한 번 눌러 사용할 수 있게 유지한다. 전체 / 계획 / 기록 필터로 교체하지 않는다.
- 상단 기상 / 수면 예상 / 집중 / 만족도 / 이행 카드의 현재 배치와 값 표시를 유지한다. 제목 옆 작은 아이콘으로 구분을 돕는다.
- 짧은 기록 블록은 기존처럼 점수 숫자로 간소화한다.
- 같은 활동이라도 점수가 달라지는 구간은 나눠 표시한다. 평균 점수 하나로 합쳐 표시하지 않는다.
- 아라 캐릭터, 표정, 위치, 크기, 말풍선, 질문 트리거, 답변 버튼, 접기/열기를 유지한다. 인용된 GPT 대화의 아라 재설계 제안은 적용하지 않는다.
- 현재 작업은 설계이며, 앱 구현은 다음 모델이 한다.

## 2. 이번 설계의 적용 방향과 기본값

아래 수치와 짧은 블록의 세 숫자 표기는 사용자 선택을 구현하기 위한 설계 기본값이다. 새로운 사용자 발언으로 간주하지 않는다. 실제 좁은 화면 검수 결과에 따라 수치를 조정하되, 정보량을 늘리거나 기존 조작을 바꾸려면 다시 의논한다.

- 한 시간은 계획 6칸 / 기록 6칸, 한 칸은 10분이다. 시간축, 선택 단위, 저장 단위는 유지한다.
- 시간별 큰 외곽 카드·그림자를 없애고, 시간 행 사이에 옅은 가로선만 둔다.
- 하나의 활동은 내부 10분 칸 경계와 반복 제목이 없는 연속 블록으로 표시한다. 활동 사이에는 경계가 남는다.
- 빈 기록 영역은 투명하게 한다. 빈칸도 기존 면적 그대로 터치·드래그할 수 있다.
- 계획은 옅은 카테고리 색, 실제 기록은 같은 계열의 더 분명한 색을 사용한다.
- 반복적인 계획 / 실제 글자 라벨은 추가하지 않는다. 과거 사용자가 제거를 요청했던 표시다. 접근성 이름에는 레인을 명시한다.
- 넓은 기록은 활동명·기간·집중 게이지·만족도 표정, 좁은 기록은 활동명·점수 숫자를 표시한다.
- 기상·취침·끼니·버퍼 알고리즘, 점수 산식, 노션·알림·동기화·체크리스트 로직은 이번 디자인 변경의 대상이 아니다.

## 3. 상단 카드와 색상 전환 탭

### 3.1 카드 아이콘

현재 다섯 카드의 순서, 폭 비율, 높이, 클릭 기능, 숫자 단위와 날짜 줄을 유지한다. 카드 제목 왼쪽에 12px 아이콘, 제목과의 간격 3px을 기본값으로 둔다. 공간이 좁으면 아이콘을 10px까지 줄이고 텍스트와 숫자 크기는 유지한다.

- 기상: 지평선 위 해.
- 수면 예상: 초승달.
- 집중: 과녁.
- 만족도: 미소 얼굴.
- 이행: 원 안 체크.

동일한 선 굵기와 16×16 viewBox를 가진 작은 inline SVG를 사용한다. currentColor로 제목 색을 따르며, 각 카드에 새 배경색을 추가하지 않는다. 아이콘은 aria-hidden=true, focusable=false로 설정하고 기존 제목을 접근성 이름으로 유지한다. 이모지는 기기마다 크기·모양이 달라지므로 사용하지 않는다. 새로운 이미지 다운로드나 캐릭터 생성은 필요 없다.

카드 숫자는 기존 값 그대로다. 만족도 옆 /5, 수면 예상의 +1, 이행 상세 열기 동작을 보존한다. 새로운 점수 정규화나 상한 표기를 넣지 않는다. Android 상단 여백은 현재 18px 및 safe-area 처리 정책을 유지하고 이 작업 때문에 추가하지 않는다.

### 3.2 색상 전환

세 탭의 순서와 한 번 탭하는 동작을 유지한다. 기존 높이를 늘리지 않고 선택된 탭만 포인트 색으로 표시한다. 선택되지 않은 탭은 중립 색을 사용한다. 메뉴로 숨기거나 가로 스크롤시키지 않는다.

- 카테고리 모드: 실제 기록은 카테고리 색, 계획은 그보다 옅은 동일 계열 색.
- 집중 / 만족도 모드: 실제 기록 배경을 해당 점수의 단일 계열 명도로 표시한다. 계획은 중립적인 옅은 표시를 유지한다.
- 빈 기록은 세 모드 모두 투명하게 유지한다. 만족도 기본 2 또는 사용자가 정한 빈칸 점수는 집계 규칙일 뿐 기록이 아니다. 빈칸의 집계 기여는 그대로 두고 배경색과 숫자만 그리지 않는다. 기존 설정의 빈칸 집계 안내는 유지한다.
- 선택·현재 시각·길이 조절 표시는 배경을 덮어쓰지 않고 외곽선 또는 얇은 테두리로 표시한다.

## 4. 시간표 레이아웃

390px 화면 기준 초기 치수:

- 시간표 좌우 여백 8px, 시간 표시 열 30px, 시간 열과 활동 영역 간격 4px.
- 활동 영역은 minmax(0,1fr) 6열. 열 간격은 0으로 두어 한 활동 내부가 끊기지 않게 한다.
- 계획 레인 높이 24px, 기록 레인 높이 36px, 두 레인 사이 간격 3px.
- 한 시간 행의 위·아래 여백 각각 4px. 시간 구분선 1px. 행 높이 목표 약 72px.
- 서로 다른 활동 경계에는 각 블록 안쪽 여백으로 총 2px 정도의 틈을 둔다. 틈은 입력 좌표에 빈 시간이 생겼다는 뜻이 아니다.
- 시간 숫자는 현재 스타일을 우선 유지한다. 자정 이후 00 +1처럼 날짜 이월 표시를 보존한다.

.hour는 시간 묶음이라는 DOM 구조와 접근성 구획으로 남겨도 된다. 시각적인 background, box-shadow, 큰 border-radius, 사방 border를 제거한다. 빈 계획 레인은 매우 옅은 중립 밑바탕 또는 기준선으로 높이를 알 수 있게 하고, 빈 기록 레인은 투명하게 둔다. 빈칸마다 둥근 네모 테두리를 그리지 않는다.

상단 00 / 10 / 20 / 30 / 40 / 50 눈금은 실제 6열과 같은 좌우 기준을 사용한다. 시간표 전체를 관통하는 진한 세로선은 넣지 않는다. 선택·드래그 중 필요한 시간 행에만 가벼운 10분 구획을 나타낸다.

계획 블록은 옅은 채움과 가는 테두리, 기록 블록은 더 분명한 채움으로 구분한다. 채워진 활동의 모서리는 7px 정도로 둔다. 크림·그린 테마는 상단과 포인트에 남기고, 배경·빈칸을 과하게 초록색으로 칠하지 않는다. 라이트/다크 모두 사용자 지정 파스텔 카테고리 색을 원색 데이터로 보존한다.

기존 취침 전 소등 시간대의 옅은 배경 구분은 유지한다. 이는 시간대 안내 배경이며 개별 빈 기록칸의 채움이나 활동 블록으로 표현하지 않는다. 예상 수면 1칸, 현재 시각 표시, 선택 범위 표시가 이 배경과 구별되어야 한다.

## 5. 블록 정보와 짧은 블록

### 5.1 표시 밀도

판정은 활동 전체 시간이 아니라 현재 화면에 나타난 한 구간의 실제 폭으로 한다. 예를 들어 90분 활동도 09:50~10:00 조각은 짧은 블록이다. 초기 기준은 폭 140px 미만이면 compact, 이상이면 expanded다. 화면 폭에 따라 자동으로 달라질 수 있다. CSS container query 또는 행 폭을 한 번 측정한 결과로 판단하며, 모든 칸에 getBoundingClientRect를 반복 호출하지 않는다.

계획 블록:
- 짧은 구간: 활동명만 한 줄, 넘치면 말줄임.
- 넓은 구간: 활동명과 기간. 점수는 표시하지 않는다.

기록 블록 compact:
- 첫 줄: 활동명, 글자 크기 기본 11px. 기존 카테고리/활동 이름을 유지한다.
- 둘째 줄: 집중·만족·이행 순서로 예를 들어 3·2·7. 기존 cellRatings()의 순서를 따른다. 숫자는 기본 10px, tabular-nums를 적용한다.
- 산출 불가 이행은 —, 실제 0은 0이다. 3·2·—를 임의로 3·2·0으로 바꾸지 않는다.
- 시간 범위, 기간, 게이지, 표정, 세 점수의 긴 이름은 이 작은 블록에 중복 표시하지 않는다. 기존 탭 메뉴로 상세를 확인한다.
- 1칸에도 활동명이 식별되도록 이름을 우선한다. 전체 시간표를 가로로 넘치게 하거나 숫자를 칸 밖으로 흘리지 않는다.

기록 블록 expanded:
- 첫 줄: 활동명, 오른쪽에 해당 점수 구간의 기간. 길이가 부족하면 기간부터 숨기고 활동명은 남긴다.
- 둘째 줄: 집중 게이지와 만족도 표정. 집중 게이지는 원형 점 5개 대신 하나의 가는 연속 막대이며 채움 비율은 점수/5다. 0점은 빈 트랙, 5점은 가득 찬 트랙이다.
- 게이지 높이 기본 4px, 폭 32~52px, 만족도 표정 14px. 표정은 기존 점수-표정 매핑을 재사용한다.
- 이행 숫자와 별도의 작은 이행 비교 막대를 추가하지 않는다. 위 계획과 아래 실제 기록의 위치·길이를 비교하게 한다. 상단 이행 점수와 상세 메뉴는 유지한다.
- compact의 세 숫자와 expanded의 게이지·표정을 동시에 표시하지 않는다.

짧은 블록에서 이행 숫자를 쓰는 것은 기존 숫자 표현을 유지하기 위한 기본값이다. 넓은 블록에서 이행 숫자를 제거하는 규칙과 구별한다. 점수 계산 자체는 어느 밀도에서도 동일하다.

### 5.2 점수가 달라질 때

09:00~10:00 작업이 앞 30분 집중 2 / 만족 3, 뒤 30분 집중 5 / 만족 3이면, 09:00~09:30과 09:30~10:00 두 블록으로 표시한다. 카테고리·집중·만족도 어느 보기에서도 이 경계를 유지한다. 대표 집중도 3.5로 합치지 않는다.

설계 기본값으로 화면에 표시하는 세 점수 중 하나라도 달라지면 시각적 구간을 나눈다. 이행은 기존 엔진에서 계산된 값과 그에 연결된 활동을 사용한다. 표시에 맞추려고 이행 점수를 새로 계산하지 않는다.

같은 카테고리라는 이유만으로 서로 다른 과제, 끼니, 식사 준비, 메모, 원래 활동을 합치지 않는다. 서로 떨어진 두 활동 사이의 빈칸을 이어 붙이지 않는다. 저장된 block ID, taskId, mealId, prepFor, 점수와 메모를 보존한다.

## 6. 시간 경계와 계획 비교

09:50~10:30 활동은 09시 오른쪽 1칸과 10시 왼쪽 3칸에 표시한다. 두 시간 행을 덮는 커다란 사각형이나 대각선 연결선을 만들지 않는다.

- 같은 원본 활동의 조각은 같은 색을 사용한다.
- 시간 행 끝에서 잘리는 모서리는 덜 둥글게 하고 안쪽에 작은 이어짐 표시를 둔다. 실제 시작/끝 모서리는 둥글게 유지한다.
- 각 시간 행에 활동명을 최대 한 번 표시한다. 이어지는 행에도 짧은 이름을 보여 위 행이 화면 밖으로 나가도 알아볼 수 있게 한다.
- 기간은 점수 구간의 총 길이다. 예를 들어 09:50~10:30이 점수 변화 없이 이어지면 40분이다. 화면에서 잘린 10분과 30분을 서로 다른 활동 길이로 잘못 설명하지 않는다.
- 실제 시작·종료에만 편집 손잡이를 붙인다. 단순히 시간이 바뀌어 잘린 조각의 모서리에 새로운 손잡이를 만들지 않는다.
- 자정 경계도 같은 규칙을 적용하고 기상일 기준 기록 정책을 바꾸지 않는다.

계획/실제의 위치 차이는 현재 화면의 시간 비교다. 자동 조정된 현재 계획과 기존 이행 계산에 사용된 기준 계획이 다를 수 있으므로, 이 시각 비교가 곧 상단 이행 점수의 산식이라고 설명하지 않는다. 기존 이행 상세의 기준을 유지한다. 원래 계획·이전 계획·현재 계획을 UI에서 임의로 섞지 않는다.

## 7. 상호작용 계약

- 계획→실제 드래그 복사, 같은 레인에서 이동, 레인 고정 범위 선택, 여러 시간에 걸친 선택을 보존한다.
- 빈칸 드래그 후 멈춤→카테고리 선택→점수, 이미 기록된 곳 탭→점수 메뉴, 집중·만족 연속 입력을 보존한다.
- 가장자리 길이 조절, 삭제, 실행취소, 체크리스트 기록 연결, 현재 시간 표시를 보존한다.
- 세로 스크롤을 범위 선택으로 잘못 처리하지 않는다. 기존 제스처 임계값을 디자인 수정에 끼워 바꾸지 않는다.
- 새로운 시각 블록은 기본 pointer-events:none이다. 기존 data-lane/data-index를 가진 10분 입력 칸이 실제 입력을 받는다.
- 점수 구간이나 시간 경계에서 시각적으로 나뉘어도 편집 대상은 원본 저장 블록 ID에 연결한다. 한 원본 블록의 여러 조각은 기존 편집 범위를 함께 강조한다.
- 서로 다른 원본 ID를 하나의 이동 가능한 블록처럼 보이게 묶지 않는다. 기존 엔진이 이미 병합한 저장 블록은 하나로 표시할 수 있다. 묶음 이동을 구현하려고 새 저장 명령을 추가하는 것은 이번 범위 밖이다.
- 선택 외곽선과 손잡이는 활동 표시층보다 위, 기존 컨텍스트 메뉴는 시간표보다 위에 둔다. 아라의 기존 z-index와 입력 처리에는 손대지 않는다.
- 손잡이를 잡고 있는 동안 해당 DOM 노드를 제거하거나 새로 만들지 않는다.
- 이전 계획과 아라 기록 후보는 확정 활동과 분리된 기존 반투명 표현을 유지한다. 후보를 기록 데이터나 점수 집계에 섞지 않는다.

## 8. 구현 위치와 데이터 흐름

현재 확인한 파일/함수:
- mobile/index.html: .overview의 다섯 카드 제목, .color-tabs, #timeline, .ara-stage.
- mobile/mobile.css: .hour, .lanes, .lane, .tile, .actual-block-overlay, .actual-block-content, .focus-gauge, .satisfaction-face. 파일 후반에 같은 선택자 override가 있으므로 관련 규칙을 모아서 정리한다.
- mobile/mobile.js: cellRatings(), groupActualBlocks(), actualGroupRatings(), renderActualBlockSummaries(), render(), paintSelection(), beginGesture(), moveGesture().
- mobile/offline-core.js: mergeBlocks()는 이미 Score와 만족도를 포함해 저장 블록 병합을 판단한다. 디자인 작업으로 이 함수를 바꾸지 않는다.

현재 groupActualBlocks()는 점수를 제외한 키로 인접 기록을 묶고 actualGroupRatings()는 그 구간 점수를 평균 낸다. 이 렌더링 조합은 사용자 선택 B와 충돌한다. 새 표시 구간은 평균을 만들지 않고 원본 ID·점수 경계를 보존해야 한다.

권장 순수 데이터 단계:
1. 하루 view와 기존 adherenceDetails를 읽는다. 입력을 변경하지 않는다.
2. plannedBySlot[288], actualBySlot[288], actionBySlot[288]을 만든다. 기록과 이행 연결은 기존 ID/명시적인 대응 관계를 우선한다. 대응이 모호하면 임의의 같은 카테고리 활동을 선택하지 말고 이행 표시를 미확정으로 둔다. 상단 산식은 그대로 유지한다.
3. 각 원본 블록 안에서 표시 점수가 같은 연속 구간(run)을 만든다. 다른 원본 ID를 넘지 않는다.
4. 각 run을 시간 경계에서 segment로 자른다.
5. segment key를 lane/sourceId/runStart/hourStart로 구성해 해당 시간 행의 표시 DOM을 갱신한다.

표시용 객체의 최소 정보:

    lane, sourceId, runStart, runEnd, hourStart,
    segmentStart, segmentEnd, columnStart, columnSpan,
    continuesBefore, continuesAfter,
    category, title, focus, satisfaction, adherence

위치는 10분 인덱스이며 end는 미포함이다. columnStart=segmentStart-hourStart, columnSpan=segmentEnd-segmentStart다. CSS grid-column에 넣을 때만 시작에 1을 더한다. 예정 수면 시각의 특수 1칸 표시도 기존 좌표를 유지한다.

기존 실제 기록 오버레이와 새 오버레이를 동시에 실행하지 않는다. 이전 중복 노드 버그를 되살리지 않도록 시간 행마다 레인별 표시층은 최대 하나, segment key당 표시 요소는 하나로 제한한다. 더 이상 존재하지 않는 segment는 제거한다. 날짜 전환 후 이전 날짜 segment가 남으면 안 된다.

배포 파일은 기존 index.html / mobile.css / mobile.js / offline-core.js 네 파일 계약을 유지한다. inline SVG 아이콘은 이 계약 안에 넣는다. 새 에셋 파일을 임의로 참조하면 Android 서명 번들에서 누락될 수 있다. 소스 분리가 필요하면 기존 네 파일로 빌드되도록 별도 검토한다.

## 9. 성능과 접근성

- 데이터가 바뀔 때 view→표시 구간을 한 번 계산한다. pointermove마다 snapshot·점수 산정·전체 시간표 재생성을 호출하지 않는다.
- 드래그 시 선택 차이와 이동 미리보기만 requestAnimationFrame당 최대 한 번 반영한다. 저장은 기존 제스처 종료 시점의 명령 흐름을 따른다.
- 15초마다 전체 렌더링하던 방식을 복구하지 않는다. 현재 마커는 이전/새 인덱스에 해당하는 칸만 갱신한다.
- 전체 DOM을 칸마다 querySelector로 다시 찾지 않도록 인덱스 Map을 공유한다. 스타일 쓰기 사이에 computed style/geometry 읽기를 반복하지 않는다.
- .ara-stage 및 관련 함수는 성능 최적화 명목으로 변경하지 않는다. 이번 변경 때문에 아라의 렌더 호출 횟수가 늘어나는지도 확인한다.
- 각 칸의 aria-label에는 레인, 시각, 활동명, 집중·만족·이행을 보존한다. 시각 오버레이는 aria-hidden으로 중복 낭독을 막는다.
- 투명한 빈칸도 키보드로 선택 가능하고 focus-visible이 보인다. 장식 아이콘은 별도 탭 정지점이 아니다.
- 작은 글자는 크기를 계속 줄이는 대신 부가정보를 숨긴다. 애니메이션은 색·불투명도 약 120ms로 제한하고 reduced-motion을 따른다.

## 11. 완료 확인 기준

기능 사례:
- 계획 08:30~09:00 1끼니: 반복 제목 없이 30분 연속 블록 한 개.
- 기록 09:00~10:00 작업, 동일 점수: 저장 블록 한 개이면 시각 블록 한 개.
- 같은 작업 09:00~09:30 집중 2 / 09:30~10:00 집중 5: 두 블록. 보기 탭을 바꿔도 분할 유지, 3.5 평균 표시 없음.
- 집중은 같고 만족만 다르거나, 표시할 이행 값이 다른 경우도 경계 유지.
- 09:50~10:30: 오른쪽 1칸과 다음 행 왼쪽 3칸으로 연결 표시. 실제 시작/끝만 손잡이.
- 23:50~00:30: +1 표시, 날짜 범위, 원본 기록 ID 보존.
- 1칸 기록: 이름과 3·2·— 같은 숫자가 칸 밖으로 넘치지 않음. 0과 미확정 구분.
- 메모/과제/끼니/식사 준비가 다른 인접 기록을 하나로 합치지 않음.
- 빈칸 만족도 설정 2/0/제외: 집계는 기존 결과와 같고 빈칸의 기록 배경·숫자는 생기지 않음.
- 기록 생성·점수 수정·삭제·길이 조절·이동·실행취소·날짜 전환 뒤 오래된 요약 노드가 남지 않음.
- 계획→실제 복사와 실제 점수 메뉴 연속 입력이 기존처럼 동작.
- 아라 후보 탭/답변 버튼/말풍선 접기/기존 체크리스트 동작 유지.

화면 확인:
- 320 / 360 / 390 / 430px에서 라이트·다크를 각각 확인한다. 390px 높이 844px을 대표 비교 화면으로 삼되, 다른 Android 화면 크기를 대표한다고 주장하지 않는다.
- 상단 다섯 카드와 숫자 배치, 색 전환 세 탭, Android 안전 여백을 기존 화면과 비교한다.
- 한 칸·두 칸·세 칸·한 시간·여러 시간 기록의 스크린샷을 실제 렌더러에서 만든다. 별도 정적 시안으로 구현 검증을 대체하지 않는다.
- 글자 확대 환경에서 숫자 겹침·가로 넘침·아이콘 때문에 제목이 사라지는 현상이 없는지 확인한다.
- 아라와 기존 대화 버튼의 위치/크기/행동이 변하지 않았음을 비교한다.

성능 확인:
- 같은 날짜·기록으로 100회 렌더링한 뒤 segment 수가 데이터에 따른 고정 개수인지 확인한다. 이전 100개 누적 문제가 재발하면 실패다.
- 변경 전후를 같은 브라우저/fixture/화면 크기에서 비교한다. JS 처리, layout/paint, long task를 구분해 기록한다. 가상 타이머가 멈춘 측정은 폐기한다.
- 드래그 프레임 작업 P95 16.7ms 이하와 기록 반영 100ms 이하는 목표값이며, 측정 전 달성했다고 쓰지 않는다. PC 수치를 Android 실기 성능으로 표현하지 않는다.
- 기존 관련 회귀 테스트와 새 구간 분할 사례를 실행한다. 가짜 DOM 테스트 통과를 실제 WebView 화면 검증으로 표현하지 않는다.
